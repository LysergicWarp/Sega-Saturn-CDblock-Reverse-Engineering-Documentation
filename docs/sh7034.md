# SH7034 notes

Chip facts relevant to the CD-block firmware, with page references into the Renesas SH7032, SH7034
Hardware Manual, `REJ09B0272-0700`, Rev. 7.00, 31-Jan-2006 (first edition September 1994).
Page numbers are given as printed / physical PDF page.

- The manual covers SH7032 `HD6417032`, SH7034 `HD6477034`, `HD6437034`, `HD6417034` and SH7034B
  `HD6437034B`, `HD6417034B` (cover, lineup at printed 6-7 / physical 34-35).
- Body physical page = printed page + 28. Front matter physical page = roman numeral + 2.
- The manual describes the chip, not the Saturn board. The board wiring is in
  [Board](board.md). Pin numbers below are for the 112-pin QFP `PRQP0112JA-A` (formerly
  FP-112).

## Port B and Port C

- Table 16.3 (printed 449, physical 477): the 16-bit Port B data register `PBDR` is at `0x05ffffc2`,
  accessible as 8, 16 or 32 bits, initial value `0x0000`.
- Figure 2.5 (printed 20, physical 48) puts the most significant byte at the lower address, so byte
  `0x05ffffc3` with mask `0x40` is `PBDR.PB6DR` (bit 6). That is the bit behind the CDB104/CDB105
  branch difference (see
  [firmware revisions](firmware-revisions.md#pre-emphasis-output-in-the-lead-in)). In CDB105 task 6
  drives it from the pre-emphasis bit of the current track
  ([periodic status](cdblock/drive.md#periodic-status)).
  On the board it is the de-emphasis output `DEMP` ([board](board.md#audio)).
- Section 16.3.2 and Table 16.4 (printed 450, physical 478): ordinary output drives the written
  value. Ordinary input reads the pin, and writes do not reach it. Other multiplexed functions can
  also ignore the write, and enabled TPC output disables it. Power-on reset clears PBDR. Manual reset
  and sleep/standby do not.
- PFC Table 15.2 (printed 431, physical 459): `PBIOR = 0x05ffffc6`, `PBCR1 = 0x05ffffcc`,
  `PBCR2 = 0x05ffffce`.
- Section 15.3.3 (printed 437, physical 465): as ordinary I/O, PB6 direction comes from `PBIOR`
  bit 6. Section 15.3.4 (printed 442, physical 470): `PBCR2` bits 13:12 select `00` PB6 I/O, `01`
  TCLKC timer input, `10` TOCXA4 timer output, `11` TP6 pattern output.
- Figure 1.2 (printed 9, physical 37): `PB6/TP6/TOCXA4/TCLKC` is pin 104. `PC6/AN6` is pin 94 and
  `PC0/AN0` pin 87.
- Section 16.4 (printed 451-452, physical 479-480): Port C is input-only. `PCDR` at `0x05ffffd0` is
  16 bits with meaningful lower eight bits, and `0x05ffffd1` holds PC0-PC7. Writes do not reach the
  pins and upper-byte reads are undefined. During A/D sampling the sampled input reads as 1.
- CDB106 reads PC0 at reset as a drive strap
  ([firmware revisions](firmware-revisions.md#drive-strap)). The board ties PC0..PC7 to ground,
  except PC0 on CDB106 boards with a 20-pin drive ([board](board.md#test-pads-and-other-pins)).
- Source discrepancy: Table 16.5 labels PCDR R/W, while section 16.4.2, its bit diagram and
  Table 16.6 describe read-only inputs with ignored writes. Treat it as read-only.

## Interrupts, DMA and serial

- Exception Table 4.2 (printed 55, physical 83) and the calculation in Table 4.3 (printed 56,
  physical 84): reset vectors use fixed offsets, other exceptions use `VBR + 4 * vector number`.
  This governs the disc extension's VBR assignment.
- Interrupt vectors and priorities: Table 5.3 (printed 72-73, physical 100-101). DMA completion
  vectors 72, 74, 76 and 78, SCI0 vectors 100-103, SCI1 vectors 104-107.
- Bus controller block diagram and pins: printed 104-105, physical 132-133. DRAM multiplexing,
  timing and refresh: sections 8.5.1-8.5.6, printed 145-161, physical 173-189.
- Four-channel DMAC, the direct memory access controller: section 9, printed 179, physical 207.
  Modes and requests from printed 192, physical 220. Examples cover RAM to external device, SCI to
  external memory and A/D transfers (printed 217-219, physical 245-247).
- Two SCI channels: sections 13.1.3-13.1.4, printed 355-356, physical 383-384. SCI0 registers are
  `0x05fffec0..0x05fffec5` and SCI1 `0x05fffec8..0x05fffecd`, ordered as mode, bit rate, control,
  transmit, status and receive (Table 13.2).
- Figure 1.2 (printed 9, physical 37), 112-pin package: RxD0 pin 107/PB8, TxD0 pin 108/PB9, RxD1
  pin 109/PB10, TxD1 pin 110/PB11, SCK0 pin 111/PB12, SCK1 pin 112/PB13. On the board SCI0
  carries the drive link, and SCI1 reaches test pads TP1 (SCK1), TP2 (TxD1) and TP3 (PB10)
  ([board](board.md)). They are unrelated to the rear SH-2 serial port.
- PFC serial pin selection: section 15.3.4, printed 438-441, physical 466-469. Serial interrupts
  and DMA: section 13.4, printed 407, physical 435.

## ITU channels 0 to 2 and the DMAC

The ITU is the chip's 16-bit integrated timer pulse unit (Table 1.1, printed 4 / physical 32),
with channels 0 to 4 (Table 10.1, printed 225 / physical 253).

- Table A.2 (printed 561 / physical 589): `TIER0` `0x05ffff06`, `TSR0` `0x05ffff07`, `TIER1`
  `0x05ffff10`, `TSR1` `0x05ffff11`, `TIER2` `0x05ffff1a`, `TSR2` `0x05ffff1b`. Each TIER holds
  OVIE, IMIEB and IMIEA in bits 2..0, each TSR the matching flags OVF, IMFB and IMFA.
- Table A.2 (printed 563-564 / physical 591-592): `DMAOR` `0x05ffff48`, and the channel control
  registers `CHCR0` `0x05ffff4e`, `CHCR1` `0x05ffff5e`, `CHCR2` `0x05ffff6e` and `CHCR3`
  `0x05ffff7e`. Channel n starts with `SARn` at `0x05ffff40 + 0x10 * n`.
- The CDB105 [restart](cdblock/kernel.md#restart) clears TIER0..2 and TSR0..2 and writes DMAOR and
  the CHCR of each DMA channel again.

## DMA channel 0

[Sector reads](cdblock/sector-reads.md) use channel 0 to copy each sector from the decoder into its
slot.

- Table A.2 (printed 563 / physical 591): channel 0's registers are `SAR0` `0x05ffff40`, `DAR0`
  `0x05ffff44`, `TCR0` `0x05ffff4a` and `CHCR0` `0x05ffff4e`, with `DMAOR` at `0x05ffff48` (bit 0
  DME).
- Section 9.2.3 (printed 185 / physical 213): TCR holds the number of transfers, bytes or words.
- Section 9.2.4 (printed 185-189 / physical 213-217): CHCR bits 15..14 DM and 13..12 SM set the
  destination and source address modes, 11..8 RS the request source, then AM, AL, DS, TM, TS, IE,
  TE and DE in bits 7..0.
- CDB105 writes `CHCR0` = `0x436d`: destination incremented (DM `01`), RS `0011` (external request
  on DREQ, single address mode, from a device with DACK to memory), DACK active-low (AL), DREQ on
  its falling edge (DS), cycle steal (TM 0), word transfers (TS), the end interrupt enabled (IE) and
  the channel enabled (DE). The source address mode does not apply in this direction.
- TE is set when TCR reaches 0 and is cleared by reading it as 1 and writing 0. With IE set it
  requests DEI. CDB105 reads CHCR0 before each new setting. `0x4368` is the same setting with IE and
  DE clear.
- Table 5.3 (printed 72 / physical 100): DEI0 is vector 72 at `VBR+0x120`, with priority in
  `IPRC[15:12]`, which DMAC channel 1 shares. CDB105 startup writes `0x8600` to IPRC (`0x05ffff88`)
  together with IPRD, so channels 0 and 1 have priority 8 and channels 2 and 3 priority 6. ROM
  longword `0x0120` points to `0x5b38`.

## DMA channel 1

[Data transfers](cdblock/data-transfer.md) use channel 1 between the buffer and the host interface.

- Table A.2 (printed 563 / physical 591): `SAR1` `0x05ffff50`, `DAR1` `0x05ffff54`, `TCR1`
  `0x05ffff5a` and `CHCR1` `0x05ffff5e`.
- Section 9.2.4 (printed 185-189 / physical 213-217): CDB105 writes `CHCR1` = `0x125d` to send to
  the host: source incremented (SM `01`), RS `0010` (external request on DREQ, single address mode,
  from memory to a device with DACK), DACK active-low, DREQ on low level (DS 0), burst (TM 1), word
  transfers, IE and DE. `0x435d` receives from the host: destination incremented (DM `01`), RS
  `0011` (from a device with DACK to memory), otherwise the same. `0x1258` is the send setting with
  IE, TE and DE clear.
- In single address mode the address mode bits are ignored for the device with DACK. CDB105
  writes `0x0a000000` as the device-side address in both directions.
- Section 9.2.3 (printed 185 / physical 213): during a transfer TCR holds the remaining count.
  Command `06` reads it to work out how many words moved.
- Table 5.3 (printed 72 / physical 100): DEI1 is vector 74 at `VBR+0x128`, in `IPRC[15:12]` with
  channel 0 (priority 8), ranked below DEI0 within the module. ROM longword `0x0128` points to
  `0x2492`, which clears DE, TE and IE with a byte write to the low byte of CHCR1.

## DMA channels 2 and 3

The [card checks](cdblock/extensions.md#card-checks) send words to the MPEG card on channels 2 and
3, one word per input capture on ITU channel 1 or 0.

- Table A.2 (printed 563-564 / physical 591-592): channel 2's registers start with `SAR2` at
  `0x05ffff60`, channel 3's with `SAR3` at `0x05ffff70`, each followed by DAR at +4, TCR at +10 and
  CHCR at +14.
- Section 9.2.4 (printed 187 / physical 215): RS `1000` and `1001` select the ITU0 and ITU1
  input capture or compare match A interrupt (IMIA0, IMIA1) as the request, in dual address mode.
- CDB105 writes `CHCR2` = `0x1908` and `CHCR3` = `0x1808`: fixed destination (DM `00`), source
  incremented (SM `01`), IMIA1 or IMIA0, cycle steal, word transfers, with IE and DE clear. It then
  sets DE with a byte write and waits for TE.
- Table A.2 (printed 561 / physical 589): `TIOR0` is `0x05ffff05` and `TIOR1` `0x05ffff0f`.
- Section 10.2.10 (printed 249 / physical 277): TIOR bits 2..0 (IOA2..IOA0) = `101` make GRA an
  input capture register on the falling edge of its input. Bit 3 is reserved and reads 1. CDB105
  writes `0x0d` to TIOR1 and TIOR0 and sets IMIEA, bit 0 of TIER1 and TIER0.
- On the board TIOCA1 and TIOCA0 are the MPEG card's video and audio data requests
  ([board](board.md#mpeg-card)).

## IRQ7

- Table 5.3 (printed 72 / physical 100): IRQ7 is vector 71 at `VBR+0x11c`, with priority in
  `IPRB[3:0]`. Task 5's setup sets it to 8. ROM longword `0x011c` points to `0x5bdc`.
- The handler reads the decoder flags at `0x0a000006` and their enables at `0x0a00000a`
  ([sector reads](cdblock/sector-reads.md#sector-pulse)). On the board IRQ7 is the interface chip's
  `IRQ H` output, raised on a sector header or a subcode frame ([board](board.md#interrupts)).

## ITU channel 4

- Table A.2 (printed 562 / physical 590): `TCR4` `0x05ffff32`, `TIOR4` `0x05ffff33`, `TIER4`
  `0x05ffff34` (bit 0 IMIEA, bit 1 IMIEB, bit 2 OVIE), `TSR4` `0x05ffff35` (bit 0 IMFA, bit 1 IMFB,
  bit 2 OVF), `TCNT4` `0x05ffff36`, `GRA4` `0x05ffff38` and `GRB4` `0x05ffff3a`.
- Table A.2 (printed 561 / physical 589): `TSTR` `0x05ffff00` bit 4 (STR4) starts channel 4.
- Table 5.3 (printed 73 / physical 101): IMIA4 is vector 96 at `VBR+0x180` and OVI4 vector 98 at
  `VBR+0x188`, both with priority in `IPRD[7:4]`. Table 5.2 (printed 69 / physical 97) places IPRD
  at `0x05ffff8a`.
- Section 10.2.9 (printed 247 / physical 275): TCR TPSC2..0 = `011` selects the internal clock φ/8.
- CDB105 startup writes TCR4 = 3, TIOR4 = 0 and TIER4 = 4 (OVIE), sets STR4 and writes `0x6666` to
  IPRD, so ITU4's interrupts run at priority 6. Traps `0x24` and `0x25` read TCNT4, write GRA4,
  clear IMFA and set or clear IMIEA ([timers](cdblock/kernel.md#timers)). ROM longword `0x0180`
  points to `0x1c90` and ROM longword `0x0188` to `0x1c70`.
- Table 5.3 (printed 73 / physical 101): IMIB4 is vector 97 at `VBR+0x184`, in `IPRD[7:4]` with the
  other ITU4 interrupts. CDB105 uses compare match B for messages from interrupt handlers:
  `TRAPA 0x2d` writes GRB4, clears IMFB and sets IMIEB
  ([posting from interrupts](cdblock/kernel.md#posting-from-interrupts)).
  ROM longword `0x0184` points to `0x1d38`.
- The sector pulse's time at `0x5e40` reads TCNT4 and adds one to the time high part while OVF is
  set.

## ITU channel 3 and SCI0

The [drive link](cdblock/drive.md#link) uses an ITU3 input capture as its strobe and SCI0 for the
bytes.

- Table A.2 (printed 562 / physical 590): `TIOR3` `0x05ffff23`, `TIER3` `0x05ffff24` (bit 1
  IMIEB), `TSR3` `0x05ffff25` (bit 1 IMFB).
- Section 10.2.10 (printed 248 / physical 276): TIOR bits 6..4 (IOB2..IOB0) = `101` make GRB an
  input capture register on the falling edge of its input. Section 10.2.11 (printed 250 / physical
  278): an input capture sets IMFB, cleared by reading it set and writing 0. Section 10.2.12
  (printed 251 / physical 279): TIER bit 1 enables the IMIB interrupt.
- Table 5.3 (printed 73 / physical 101): IMIB3 is vector 93 at `VBR+0x174` with priority in
  `IPRD[11:8]`. SCI0 receive (RxI0) is vector 101 at `VBR+0x194` with priority in `IPRD[3:0]`.
- Section 15.3.4 (printed 443 / physical 471): `PBCR2` bits 7..6 = `10` select TIOCB3 on PB3, bits
  5..4 = `00` leave PB2 as ordinary I/O.
- Section 13.2.5 (printed 358 / physical 386): SMR bit 7 (C/A) = 1 selects clocked synchronous
  mode, always eight data bits.
- Section 13.2.6 (printed 360-363 / physical 388-391): SCR bit 6 (RIE) enables the receive
  interrupt, bits 5 and 4 (TE, RE) the transmitter and receiver. With CKE1..0 = `00` in synchronous
  mode the clock is internal and SCK is its output. Transmission starts when TDRE is cleared after
  TDR is written.
- Section 13.2.7 (printed 363-364 / physical 391-392): SSR bit 7 is TDRE and bit 6 RDRF. Status
  flags clear only by writing 0 after reading them set.
- Table 13.4 (printed 372 / physical 400): in clocked synchronous mode with SMR's clock select at
  0, BRR 99 gives 50,000 bit/s at 20 MHz. A byte takes 160 µs, 3,200 cycles.
- CDB105 startup writes SMR0 `0x80`, BRR0 `0x63` and SCR0 0, `PBCR2` `0x008a`, `PBIOR` `0x3af0`
  (PB2 and PB3 inputs, PB6 output) and IPRD `0x6666`. Task 6 setup writes SCR0 `0x30` and ORs
  `0x50` into TIOR3 and `0x02` into TIER3. ROM longword `0x0174` points to `0x973c` and ROM longword
  `0x0194` to `0x987c`.

## IRQ6

- References: Table 4.10 (64 / 92), Table 5.2 (69 / 97), sections 5.2.3 and 5.2.5 (70-72 / 98-100),
  sections 5.3-5.4.1 (74-78 / 102-106).
- IRQ6 is an external interrupt input, vector 70 at `VBR+0x118`. Its priority is `IPRB[7:4]` in
  register `0x05ffff86`. Priority 0 disables it. Otherwise the request priority must exceed `SR.I`.
  Acceptance stacks SR then PC and copies the accepted priority into `SR.I` before jumping to the
  vector.
- `ICR` is `0x05ffff8e` and IRQ6 sense is bit 1: zero selects low level, one selects falling edge.
  A level request stays pending while the input is asserted, and deasserting it before acceptance
  removes the request. How the external device acknowledges is outside this manual.
- CDB105 startup clears ICR, task5 sets the IPRB low nibble to 8 (IRQ7), and task14 ORs `0x0060`
  into IPRB (IRQ6 priority 6 under the retained reset value). The idle SR `0x20` masks levels up
  to 2. ROM longword `0x0118` points to `0x1f40`.
- On the board IRQ6 is the interface chip's `IRQ L` output. It is asserted when the host writes CR4
  and stays asserted until the handler clears the command flag at `0x0a000004`
  ([board](board.md#interrupts)).

## Instruction timing

- Table 2.13 (printed 36 / physical 64): `ADD #imm,Rn` and `CMP/EQ #imm,R0` take 1 cycle.
- Table 2.16 (printed 39 / physical 67): `BF` and `BT` take 3 cycles when they branch and 1 when
  they do not.
- These counts put the CDB105 header delay at 5 cycles per iteration
  ([trusted-ID shortcut](cdblock/disc-authentication.md#trusted-id-shortcut)).
